# 夢をはぐくむ：実装・AI接続・運用

## 現在の状態

UI、明示したモック体験、4回答の対話、編集プレビュー、通常絵馬と混在する桜縁の予祝絵馬、下書きの再開、サーバー用APIコードを実装しています。有料サービスの契約・有効化、外部AIへの実送信、公開バックエンドの設置は行っていません。初期状態はモックのみです。モデル固有の文章品質と実際の課金額は未検証です。

GitHub Pagesの静的公開方式はそのままです。追加の画像・音声・依存パッケージは不要です。React画面は `src/YoshukuExperience.tsx`、型・モック・APIクライアントは `src/yoshuku.ts`、外観は `src/yoshuku.css`、既存データへの追加保存は `src/store.ts` にあります。

## 体験

絵馬殿の「夢をはぐくむ」、または絵馬詳細の「この夢をはぐくむ」から開始します。最初は固定した感情の質問、その後に情景・思い・自分への言葉をたずねる4回答の構成です。質問は一問ずつ、言い換えも可能です。モックは規則による文章の引用・組み立てであり、AIとして表示しません。自由な要約品質を持つものではありません。長い回答はモック要約時に一部を引用し、全文は対話履歴に残します。

プレビューは自由に編集でき、奉納操作まで確定しません。予祝は想像であることを画面に明記し、夢の達成や小判付与は行いません。既存絵馬から始めたときは同じIDを更新し、元の詳細・登録日・目標日・期待度を保持します。新しい絵馬だけ既存の夢登録処理を通します。奉納済みの文章は従来の編集画面から再編集できます。

## 保存・互換性

既存キー `yumekana-shrine:v1`、version 1を維持します。Dreamに任意の `emaType: 'normal' | 'yoshuku'`、`yoshuku` を追加。旧レコードを一括書き換えません。予祝には `originalWish`、`generatedText`、`confirmedText`、`createdAt`、`updatedAt`、`conversation`、`mode` を保存します。桜の装飾は種類から復元します。

下書きは `yumekana-shrine:yoshuku-draft:v1` に別保存し、未送信の入力、対話、プレビュー編集も再開できます。閉じても、リロードしても残ります。APIエラー時は回答を確定済みの対話に進めず、入力を保持して再試行します。奉納は端末への書き込み成功後のみ完了扱いにします。元絵馬が削除・達成済みの場合は勝手に再作成しません。別の下書きがあれば自動では上書きせず、利用者が明示的に破棄できます。壊れた下書きも明示的な破棄までは保護します。

現在の下書きは端末ごとに一つです。複数タブの同時編集や異なる端末・オリジン間の自動同期は対象外です。公開サイトのlocalStorageとローカル環境のデータは別物で、この機能追加によって自動マージはされません。

## AI連携の構成と概算費用（有効化前に確認が必要）

- UI・モック：追加サービス不要、API料金0円。
- 実AI：Pages → HTTPSバックエンド → OpenAI Chat Completions API。Node.js 24で動く単一プロセスと永続ディスクが必要です。既存のサーバーがあれば追加の固定費0円の場合もありますが、新規ホスティングの固定費は選定先によって異なり、未契約です。
- AI従量費：モデルを選んでいないため円額は未確定です。1体験は通常4回のAPI呼び出し（質問3回＋要約1回）、言い換え・再試行は追加です。計算式は `(入力トークン × 選定モデルの入力単価 + 出力トークン × 出力単価)`。短い回答で1体験の入力合計を約4,000〜8,000トークン、出力合計を約800〜1,500トークンと仮置きして見積もれますが、実測値ではありません。仮に単価が入力100万トークンあたりUS$1、出力US$4なら約US$0.0072〜0.014/体験です。これは算式の例であり、特定モデルの現行価格ではありません。
- 初期上限：全体で100リクエスト/UTC日、IP単位で12/UTC日、6/分、全体同時2件、出力上限512トークン/リクエスト。言い換えなしなら全体で最大25体験/日相当（途中終了・失敗も枠を使用）。料金の上限設定はプロバイダー側でも確認してください。金額そのものをこのコードで検証するものではありません。

**契約先・モデル・料金と許容上限を確認してから、実AIを有効化してください。APIキーをVITE_*、ソースコード、Pages設定の公開変数に入れてはいけません。**

## ローカルでのAI接続（承認後の作業）

1. `server/.env.example` を `server/.env` にコピーします（git対象外）。サーバー専用のAPIキー、JSON出力と `max_completion_tokens` に対応するモデル、ランダムな32文字以上の `YOSHUKU_QUOTA_SECRET` を設定します。制限用シークレットは `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` などで生成できます。
2. 料金を確認・承認した後に限り `YOSHUKU_AI_ENABLED=true` にします。
3. ルートの `.env.local` に `VITE_YOSHUKU_API_URL=http://127.0.0.1:8787/api/yoshuku` を設定し、フロントを再起動します。これは公開してよい接続先URLだけです。
4. `npm run yoshuku:server` と `npm run dev` を別ターミナルで起動します。外部AIを使うチェックと、外部送信への同意をしてから進めます。リロード後は同意を取り直します。

設定しなくても `npm run dev` だけでモック体験を確認できます。サーバーも初期設定は503応答で、外部通信をしません。

## 公開バックエンドの運用条件

- HTTPSのリバースプロキシで `/api/yoshuku` に転送し、許可Originを `https://komiki0401.github.io` に限定。フロントはビルド時に `VITE_YOSHUKU_API_URL` を設定します。今回の公開ワークフローは `VITE_YOSHUKU_API_URL` を空に固定し、モックのみ公開します。実AIを有効にする承認を得た後、GitHubのActions Variablesに `YOSHUKU_API_URL` としてバックエンドURLを登録し、ワークフローのビルド用 `VITE_YOSHUKU_API_URL` にその変数を渡すよう変更します。URLだけが公開用で、キーはサーバー側に置きます。Pagesの公開方式は維持します。
- サーバー専用の環境変数・シークレット管理を使用し、APIキーをGit・ログ・レスポンスへ出しません。既存の夢一覧・小判・感謝・図鑑は送らず、その願いと今回の質問・回答だけを送ります。サーバーは会話本文を永続化せず、制限用のIPは日付付きHMACで記録します。外部AI側のデータ取り扱いも運用者が利用者へ案内してください。
- 制限ファイルは永続ボリュームに保存し、一つのNodeプロセスだけで運用してください。再起動で制限はリセットされません。複数プロセス・サーバーレスで運用するなら、先に共有DB/レート制限へ置き換える必要があります。ファイル破損・保存失敗時はAIへの送信を止めます。ファイルを削除・日付やシークレットを変更すると制限をリセットしてしまうため運用で避けます。
- リバースプロキシ配下は、直接アクセスを閉じ、プロキシが `X-Forwarded-For` を必ず上書きすることを確認した場合だけ `YOSHUKU_TRUST_PROXY=true` にします。初期値falseでは実際の接続元を使います。
- CORSは認証ではありません。IP制限と全体上限はありますが、一般公開前に入口側のボット対策・リクエスト制限を設け、APIプロジェクトの利用制限・監視も設定してください。共有IPでは利用枠を共有します。アプリ内に秘密の共通トークンを埋め込む対策はしません。
- 入力22KB、4回答、応答35秒まで。ユーザーの命令をシステム指示として扱わないプロンプトにし、質問が複数ある応答や形式不正は拒否して入力を残します。実モデルの品質・安全性を完全には保証しないため、実AI公開前に日本語の体験品質確認が必要です。

## 検証

`npm run test:e2e:ai`：テスト専用の架空API URLでビルドし、全通信をPlaywrightで置き換えて、外部送信への同意・4回答の連携・API失敗・連打防止・リロード後の同意と入力復元をスマホ/PCで確認します。有料APIは使用しません。GitHub Actionsでも実行し、その後に通常のビルドと回帰テストを実行して、テスト用URLを公開成果物に残しません。手元でもこのテスト後は `npm run build` で通常の成果物に戻してください。
