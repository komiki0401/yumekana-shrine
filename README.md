# 夢叶神社 🌸

**幸せは、ずっとあなたの中にあった。**

夢を絵馬に込め、毎日の小さな一歩を楽しむ、日本語のスマートフォン向けWebアプリです。React + TypeScript + Viteで動作し、通常機能はログイン・バックエンド・外部認証・課金なしで使えます。夢をはぐくむ機能の実AI連携だけは、任意のバックエンドと有料APIの別途設定が必要です（初期状態は未設定）。神社のイラストは自作SVG、音はユーザー操作後にWeb Audio APIで生成します。外部フォントや画像の通信は不要です。

## ローカル起動

クラウド環境での再開は [クラウド開発の引き継ぎ手順](docs/cloud-handoff.md) を参照してください。

Node.js 24 LTS、npm 11を推奨します。

```sh
npm ci
npm run dev
```

開発サーバーの `/yumekana-shrine/` を開きます。Viteが出力するURLを使用してください。

```sh
npm test           # 小判・保存形式・日付・おみくじの単体テスト
npm run typecheck  # TypeScript型チェック
npm run build      # 型チェックと本番ビルド（dist/）
npm run preview    # ビルド成果物のローカル確認
npx playwright install chromium # 初回のみブラウザを取得
npm run test:e2e   # ビルドとスマホ・デスクトップのブラウザテスト（46件）
```

## 基本機能

- 神社ホーム：境内を画面の横幅いっぱいに表示し、スマホは縦長の構図に対応。鳥居・本殿・桜・灯籠・賽銭箱のイラストに、紙垂のゆらめきと風に舞い落ちる桜を追加。「風をとめる」で環境演出を停止できます。叶えた夢とおみくじの状態は境内の下に表示。
- 絵馬殿：木の絵馬掛けにコンパクトな絵馬を表示（スマホ3列・PC6列）。タップすると全文・詳細・目標日を確認し、編集や達成操作ができます。「小さな夢の候補から選ぶ」では初期の20候補からランダムに4つを表示し、「別の候補を見る」で入れ替え。「さらに夢を探しに行く」を開くと9ジャンル・合計200個を探せます。3×3のジャンルカードから選択し、8件ずつ「もっと見る」で表示。ワンタップで登録でき、登録済みの候補は無効化して表示します。夢の登録・編集、任意の詳細と目標日。達成は確認画面を経て、メッセージと日付を履歴に記録。
- 叶えた夢リスト：達成した夢を半透明のシャボン玉で表示。ゆったり漂う動きを眺めたり、タップして達成日とメッセージを読み返せます。動きの一時停止と視差効果を減らす設定に対応。
- お賽銭：小判1枚を奉納。小判投入・鈴・二礼二拍手一礼の演出。音声は初期状態でオフ。右上の音声ボタンで切り替え。
- おみくじ：1日1回無料。5つの運勢、メッセージ、開運アクション、ラッキーカラー。その日の結果は固定。
- お礼参り：100種類からランダムに表示する6つの幸せを複数選択し、自然な感謝の文章に変換。自由記述は任意で、選択だけ・自由記述だけ・両方で奉納できます。「もう一度」から何度でも記録し、履歴はお礼参りとあゆみで閲覧できます。感謝度は1回＋1・ローカル日付で1日3ポイントまで。上限後も奉納・記録を続けられます。
- 境内の出会い：50種類のデータを定義し、完成した10種類だけを抽選・描画。発生率は合計、カテゴリとレアリティの傾向は感謝・期待の内訳に連動。
- 奇跡図鑑：境内のボタンから開く50枠の図鑑。未発見は「？」、発見済みは名称・説明・初回日時を表示。レアリティで絞り込めます。
- あゆみ：達成した夢のタイムライン、日別目標、純獲得小判、累計奉納数。

日付は10秒ごとの確認と画面復帰時に更新します。各操作でも現在のローカル日付を確認します。過去の目標は履歴として残し、過去日には報酬操作を行いません。端末時計の変更に対するサーバー検証はありません。

小判残高は取引履歴の合計です。絵馬の夢を初めて達成したときに小判が1枚届きます。同じ夢に重複して報酬は付与しません。以前の目標機能の記録と小判残高は保持し、過去の達成済みの夢に報酬を遡って付与しません。

## 保存と制約

`localStorage` の `yumekana-shrine:v1` に、`version`、`dreams`、`dailyGoals`、`transactions`、`fortunes`、`settings`、`gratitudes`、`spirit`、`encounters`、`spiritCredits` をまとめて保存します。各レコードにはUUIDがあります。保存処理は `src/store.ts` とUIの更新処理に集約しており、将来のエクスポート・移行処理を追加できます。

- 保存データが破損している場合、元のデータを上書きせず、一時データで画面を開いて警告します。
- 書き込み失敗時も画面は使えますが、変更はメモリ内のみとなり、警告を表示します。
- ブラウザの保存データ削除・端末変更・異なるオリジンへの移動でデータは引き継がれません。初期版にエクスポートやクラウド同期はありません。
- 同時に複数タブを編集する用途には対応していません。1つのタブで利用してください。
- システムの「視差効果を減らす」設定に対応します。達成・奉納演出はスキップ可能です。
- おみくじは娯楽です。現実の結果を保証しません。

## GitHub Pagesへの公開

1. このファイル一式を `komiki0401/yumekana-shrine` の **mainブランチ**にコミットしてpushします。
2. GitHubの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
3. **Actions → Deploy to GitHub Pages** を確認します。mainへのpushまたは **Run workflow** で実行できます。
4. テストと型チェック・ビルドに成功すると、`dist/` がPagesにデプロイされます。
5. デプロイ成功後、`https://komiki0401.github.io/yumekana-shrine/` で確認します。

`vite.config.ts` の `base` は `/yumekana-shrine/` です。リポジトリ名を変えるときはこの値も変更してください。カスタムドメインのルート配信では `/` にします。画面切り替えはクライアント内の状態で行うため、PagesのSPA用404設定は不要です。

GitHub側でPagesの利用とActionsの実行が許可されている必要があります。デプロイの成否はActionsの実行結果を確認してください。

## 夢の候補を追加するとき

`src/dreamCatalog.ts` の該当ジャンルの `suggestions` に、未使用のIDと文章を追記します。既存IDは変更・振り直しをしません。候補IDは登録した夢の任意フィールド `suggestionId` に保存され、タイトルを編集しても同じ候補の二重登録を防ぎます。旧データのようにIDがない夢は、タイトルの空白・文末の句読点を揃えて照合します。達成済みの夢と同じ願いは、再び願い中として登録できます。

候補を追加したら件数テストの期待値も更新し、`npm test` と `npm run test:e2e` を実行してください。ジャンルカードの候補数はデータから自動計算されます。

## お礼参り・保存データの互換性

保存キー `yumekana-shrine:v1` と `version: 1` を維持し、追加フィールドがなければ読み込み時に補完します。既存の夢・達成履歴・小判・感謝・演出ログを削除しません。過去の夢の数は期待度の初期値として引き継ぎます。

新しい夢（候補・手書き）で期待度が1増え、同じ夢の削除・再追加では増えません。ありがとうの奉納は1回につき感謝度＋1、ローカル日付で1日最大3ポイントです。同じ内容でも、改めて奉納したものは1回として数えます。4回目以降も記録はでき、加点だけを止めます。文字数・選択数・自由記述の有無では加点に差をつけません。数値は減らさず、日付が変わると新しい日の枠を使えます。毎日の義務・連続ボーナス・ランキングはありません。

自由記述は任意で最大1000文字。選択した自然な感謝の文章と自由記述を組み合わせて保存します。選択肢はID・元のラベル・感謝文のスナップショット、自由記述は別フィールドとして残すため、後で候補を変更しても過去の文章を保ちます。感謝の記録で小判は消費・獲得しません。鈴の音は既存の音声設定に従い、初期状態はミュートです。

## 境内レア演出・奇跡図鑑：第1段階

50種類・5カテゴリ各10種類を `src/miracleCatalog.ts` に定義しています。現在、専用の動きと描画が完成しているのは次の10種類です。

| カテゴリ | 実装済み演出 | レアリティ |
| --- | --- | --- |
| 動物 | 猫が遊びに来る／蝶が舞う | N／R |
| 自然 | 桜吹雪／虹が現れる | N／SR |
| 空・宇宙 | 流れ星／流星群 | R／SSR |
| 神秘 | 光の蝶が現れる／光の玉が浮かぶ | R／SR |
| 神様 | 神様が姿を現す／神様が微笑む | UR／SSR |

残り40種類はデータと図鑑の枠だけを用意し、抽選・発見記録から除外します。`implemented: true` の種類には `encounterImages.ts` の画像と実際の描画・アニメーションを用意してから公開してください。既存のPNG6枚は削除せず保持しています。流れ星・流星群には小さな金色のSVGを使用し、虹・光の玉も軽量なSVGで描画します。

### 抽選

- 境内を表示して約8秒後、その後約60秒ごとに抽選します。非表示タブ・別ページ・「風をとめる」の間は抽選しません。
- **発生するかどうか**：感謝度＋期待度の合計から算出する従来の3倍カーブを引き継ぎ、最大95%。合計0でも発生の余地があります。
- **発生時のレアリティ**：合計0の基本割合は N 50%、R 30%、SR 15%、SSR 4%、UR 1%。参拝1回あたりの発生確率ではありません。
- 合計が育つと高レアリティを少し増やし、両方が育つとSSR・URをさらに少し増やします。正規化して合計100%にします。
- 同レアリティ内では、感謝度が動物・自然、期待度が空・神秘、両方の値が神様カテゴリの重みに影響します。低い数値でも実装済み10種類の確率は0になりません。
- 設定は `encounters.ts` の `encounterSettings`、`encounterRate`、`rarityProbabilities`、`categoryAffinity` に集約しています。

画像を読み込んでから演出と記録を開始します。読み込み失敗・途中の画面移動では発見を保存せず、同時に複数の演出を表示しません。約18秒で終了し、閉じることもできます。画像は主要ボタンを覆う操作領域を持たず、動きを減らす設定では静止表示にします。

### 奇跡図鑑

境内左上の「奇跡図鑑」ボタンから開きます。下部ナビは6タブのままです。50枠、発見数、レアリティ別絞り込み、発見済みの画像・名称・説明・初回日時を表示します。今後追加予定の40枠は未発見のままです。

図鑑専用の重複した保存方式は増やさず、既存 `encounters` ログから初回発見を算出します。同じ演出を再発見しても、最も古い日時を表示します。以前の `miracle` は「神様が微笑む（deitySmile）」として表示し、元ログは保持します。未実装の演出は記録も集計もしません。

## お礼参りの選択式UXと日次ポイント

最初に「今日、ちょっと幸せだったことは？」を表示し、100種類からランダムに6つを並べます。「別の幸せを見る」で入れ替えられ、入れ替えても選択は保持されます。選んだ文章のプレビューから選択を外すこともできます。下に自分の言葉を任意で添え、「ありがとうを奉納する」で記録。光と花びらの後も完了画面は残り、「もう一度ありがとうを奉納する」で新しい記録を始めます。数値の表示は入力カードの下です。

`Gratitude` に任意の `selectedThanks`・`freeText`・`pointsAwarded` を追加しました。既存の `text`・UUID・ローカル日付・時刻・夢への紐づけは維持し、古い自由記述の記録もそのまま表示します。

日次の付与数は `spiritCredits.gratitudeDays` に保持します。記録削除やリロードで上限をリセットせず、同じ送信IDは二重保存・二重加算しません。旧データに日次情報がない場合は過去の記録と付与キーから補完し、過去の感謝度は減らしません。すでに当日3ポイント分以上の記録がある場合は、当日の新しい奉納は記録のみとなります。

確認済み：100候補の一意性と変換、選択のみ・自由記述のみ・両方、連打、リセット、上限後の保存、リロード保持、ローカル日付変更、選択数・文字数で加点が変わらないこと、既存データの移行、あゆみからの閲覧、スマホ幅320pxの表示。

## 夢をはぐくむ（予祝の絵馬）

絵馬殿で4往復の予祝体験を行い、文章を編集して桜縁の特別な絵馬を奉納できます。既存絵馬からも開始でき、端末内の下書きから再開できます。初期状態は明示したモック体験で、AIへの外部送信・課金はありません。通常の夢・小判・履歴は維持します。構成・保存形式・AIの接続方法・上限・費用の見積もり方法は [予祝機能の説明](docs/yoshuku.md) を参照してください。
