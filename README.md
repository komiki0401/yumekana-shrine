# 夢叶神社 🌸

**今日の小さな願いが、明日の大きな夢になる。**

夢を絵馬に込め、毎日の小さな一歩を楽しむ、日本語のスマートフォン向けWebアプリです。React + TypeScript + Viteで動作し、ログイン・バックエンド・外部認証・課金はありません。神社のイラストは自作SVG、音はユーザー操作後にWeb Audio APIで生成します。外部フォントや画像の通信は不要です。

## ローカル起動

Node.js 24 LTS、npm 11を推奨します。

```sh
npm ci
npm run dev
```

開発サーバーの `/yumekana-shrine/` を開きます。Viteが出力するURLを使用してください。

```sh
npm test           # 小判・保存形式・日付・おみくじの単体テスト
npm run typecheck  # TypeScript型チェック
npm run build      # 型チェックと本番ビルド（dist/）
npm run preview    # ビルド成果物のローカル確認
npx playwright install chromium # 初回のみブラウザを取得
npm run test:e2e   # ビルドとスマホ・デスクトップのブラウザテスト（10件）
```

## 基本機能

- 神社ホーム：鳥居・本殿・桜・灯籠・賽銭箱のイラスト、叶えた夢とおみくじの状態。
- 絵馬殿：20個の気軽な夢候補からランダムに4個を表示。候補の入れ替えとワンタップ登録、願い中の候補の重複表示を防止。夢の登録・編集、任意の詳細と目標日。達成は確認画面を経て、メッセージと日付を履歴に記録。
- 叶えた夢リスト：達成した夢を半透明のシャボン玉で表示。ゆったり漂う動きを眺めたり、タップして達成日とメッセージを読み返せます。動きの一時停止と視差効果を減らす設定に対応。
- お賽銭：小判1枚を奉納。小判投入・鈴・二礼二拍手一礼の演出。音声は初期状態でオフ。右上の音声ボタンで切り替え。
- おみくじ：1日1回無料。5つの運勢、メッセージ、開運アクション、ラッキーカラー。その日の結果は固定。
- あゆみ：達成した夢のタイムライン、日別目標、純獲得小判、累計奉納数。

日付は10秒ごとの確認と画面復帰時に更新します。各操作でも現在のローカル日付を確認します。過去の目標は履歴として残し、過去日には報酬操作を行いません。端末時計の変更に対するサーバー検証はありません。

小判残高は取引履歴の合計です。絵馬の夢を初めて達成したときに小判が1枚届きます。同じ夢に重複して報酬は付与しません。以前の目標機能の記録と小判残高は保持し、過去の達成済みの夢に報酬を遡って付与しません。

## 保存と制約

`localStorage` の `yumekana-shrine:v1` に、`version`、`dreams`、`dailyGoals`、`transactions`、`fortunes`、`settings` をまとめて保存します。各レコードにはUUIDがあります。保存処理は `src/store.ts` とUIの更新処理に集約しており、将来のエクスポート・移行処理を追加できます。

- 保存データが破損している場合、元のデータを上書きせず、一時データで画面を開いて警告します。
- 書き込み失敗時も画面は使えますが、変更はメモリ内のみとなり、警告を表示します。
- ブラウザの保存データ削除・端末変更・異なるオリジンへの移動でデータは引き継がれません。初期版にエクスポートやクラウド同期はありません。
- 同時に複数タブを編集する用途には対応していません。1つのタブで利用してください。
- システムの「視差効果を減らす」設定に対応します。達成・奉納演出はスキップ可能です。
- おみくじは娯楽です。現実の結果を保証しません。

## GitHub Pagesへの公開

1. このファイル一式を `komiki0401/yumekana-shrine` の **mainブランチ**にコミットしてpushします。
2. GitHubの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
3. **Actions → Deploy to GitHub Pages** を確認します。mainへのpushまたは **Run workflow** で実行できます。
4. テストと型チェック・ビルドに成功すると、`dist/` がPagesにデプロイされます。
5. デプロイ成功後、`https://komiki0401.github.io/yumekana-shrine/` で確認します。

`vite.config.ts` の `base` は `/yumekana-shrine/` です。リポジトリ名を変えるときはこの値も変更してください。カスタムドメインのルート配信では `/` にします。画面切り替えはクライアント内の状態で行うため、PagesのSPA用404設定は不要です。

GitHub側でPagesの利用とActionsの実行が許可されている必要があります。デプロイの成否はActionsの実行結果を確認してください。

```text
playwright.config.ts
vitest.config.ts
.github/workflows/deploy.yml
vite.config.ts
```
